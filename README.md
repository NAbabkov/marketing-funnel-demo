# Маршрут — демо маркетинговой аналитики

**[Открыть проект в браузере](https://marshrut-marketing.pages.dev/)** — установка не требуется.

Публичная версия пока не содержит раздел атрибуции и экспорт CSV, описанные ниже. Они доступны при локальном запуске текущего кода; для их появления на сайте требуется отдельное обновление развёртывания.

Учебный проект по мотивам хакатон-кейса образовательной компании. Помогает показать путь от планирования рекламного размещения до перехода на страницу продукта и условной покупки. Не является официальным продуктом компании и не использует её логотип.

## Что можно попробовать

- Посмотреть календарь демонстрационных размещений и добавить собственное размещение.
- Посмотреть в календаре исторические публикации из открытых Telegram-каналов и открыть оригинальный пост. Историческая неделя открывается при запуске; кнопка «Сегодня» возвращает к текущей дате.
- Открыть карточку размещения и перейти по его ссылке на демонстрационную страницу.
- Имитировать покупку и посмотреть изменения в общей аналитике: переходы, покупки, конверсию, расходы и условную выручку.
- Сравнить First Touch, Last Touch, Linear и Time Decay, выбрать окно и группировку, посмотреть пути покупок и скачать CSV.
- Сбросить демонстрационные данные к исходному состоянию.

Демонстрационные размещения, их названия и показатели вымышлены. В календаре также показан снимок 182 открытых постов из пяти Telegram-каналов, опубликованных в августе — сентябре 2026 года: канал, дата, краткий фрагмент, просмотры на момент сбора и ссылка на оригинал. Фрагменты сокращены, ссылки и контактные данные в них скрыты. Данные архива не означают, что посты были платной рекламой, и не связываются с демонстрационными покупками. Оплата — только кнопка-имитация: деньги не списываются, форма карты и контактов отсутствует.

## Запуск

Нужен Node.js версии 22.13 или новее и pnpm.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Откройте адрес, который выведет Vite. Для проверки выполните `pnpm test`, для сборки — `pnpm build`, затем для локального просмотра сборки — `pnpm preview`.

## Технологии

React, TypeScript и Vite; интерфейс работает без серверной части. GitHub Actions проверяет установку зависимостей, тесты, типы и сборку при изменениях кода.

## Устройство проекта

`app/page.tsx` отвечает за интерфейс и сценарии, `app/demo.ts` — за модель, начальные демо-данные и расчёты, `app/useDemo.ts` — за сохранение и обновление состояния. `app/posts.json` содержит архив публичных публикаций, которые отображаются на соответствующих датах в календаре. `app/attribution.ts` рассчитывает распределение, `app/AttributionPanel.tsx` показывает модели и фильтры. Стили находятся в `app/globals.css`. Данные имеют ключ `marketing-demo-v1` в `localStorage`.

Переход засчитывается при каждом открытии действительной ссылки, покупка — один раз на открытой странице. Конверсия равна числу покупок, делённому на число переходов; выручка — сумма условных цен покупок, расходы — сумма стоимостей размещений. Начальные события включены в показатели.

## Атрибуция в демо

В аналитике можно сравнить четыре модели: **First Touch** относит условную покупку к первому касанию, **Last Touch** — к последнему, **Linear** делит между размещениями поровну, а **Time Decay** отдаёт больший вес событиям, близким к покупке. Для Time Decay доступен период полураспада; окно поиска касаний — 7, 30 или 90 дней до покупки. События после покупки и за пределами окна исключаются. Повторные касания одного размещения объединяются: для First Touch берётся первое, для остальных моделей — последнее.

Доли подходящих размещений для каждой условной покупки в сумме составляют 100%. При отсутствии известного пути сумма попадает в «Источник неизвестен». Срезы по каналу и кампании применяются после распределения: доли отфильтрованных источников не перераспределяются. Расходы суммируются по выбранным размещениям за всё время; ROAS — условная отнесённая выручка / условные расходы, при нулевых расходах выводится прочерк. Для проверки доступны расшифровка путей и CSV; поля экспорта защищаются от формул в электронных таблицах.

Связи части начальных синтетических событий намеренно смоделированы, чтобы продемонстрировать разницу моделей. Новые действия связываются по случайному идентификатору текущего браузера. Старые пользовательские события без такого идентификатора не связываются задним числом и остаются без источника. Исторические посты Telegram не становятся касаниями покупателя. Это правила распределения демонстрационных сумм, а не доказательство причинного эффекта рекламы.

## Границы и приватность

Приложение работает целиком в браузере: сервера, базы данных, учётных записей, внешней аналитики и платёжного провайдера нет. Данные и случайный идентификатор браузера сохраняются в `localStorage` текущего браузера и доступны другим вкладкам того же сайта в нём; идентификатор нужен для демонстрации нескольких касаний и не отправляется на сервер. Сброс восстанавливает демонстрационные данные, но не удаляет этот идентификатор; его можно удалить через очистку данных сайта в браузере. Ссылки демонстрируют атрибуцию в этом же браузере; они не собирают общую статистику между браузерами или устройствами. Очистка данных сайта или сброс демо удалит локальные изменения.

Не вводите персональные данные в поля демо: любой код на том же источнике и пользователь этого браузера смогут прочитать `localStorage`. Это демонстрационный прототип, а не готовая система для публичного сбора клиентских данных или приёма платежей.

Вкладки получают обновления через событие `storage`; при поддержке Web Locks одновременные изменения выполняются последовательно. В браузерах без Web Locks одновременные записи могут конфликтовать. Если хранилище недоступно или повреждено, приложение предупреждает об этом; несохранённые изменения могут исчезнуть при закрытии страницы. Для автономной работы сначала установите зависимости: установленное приложение и сборка не обращаются к сети, но браузеру нужен локальный сервер для открытия проекта.

## Ссылка на сайт без собственного сервера

Сайт опубликован на Cloudflare Pages через Direct Upload. После изменения кода нужно выполнить `pnpm build` и загрузить содержимое `dist` как новое развёртывание в Cloudflare Pages; этот вариант не связан с GitHub автоматически.

Локальные демонстрационные данные сохраняются отдельно для каждого браузера и домена. Публичный архив доступен всем посетителям сайта. Даты публикаций в календаре показаны по московскому времени; переход к оригиналам постов требует доступа к интернету. Некоторые фрагменты содержат взрослые или разговорные формулировки из источников.
